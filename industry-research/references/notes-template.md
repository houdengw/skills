# 研究底稿模板

研究底稿记录整个研究过程中讨论确认的结论，是最终报告的原材料，也让研究可以跨多次对话继续。

每个阶段结束后更新一次。只记录结论、证据和讨论结果，不要把检索到的原始资料全部贴进来。

```markdown
# 产业研究底稿：[产业名称]

## 研究计划
- 研究对象：[整个产业 / 某个环节；包含哪些细分]
- 地域范围：
- 用途与交付：[投资决策 / 研究报告；交给谁；截止时间]
- 核心问题：
  1. ...
  2. ...
- 产业类型：[参见 industry-types.md 的分类]
- 用户已有资料与初步看法：
- 阶段安排：[哪些阶段重点研究，哪些快速带过]

## 进度
- [x] 0. 立项
- [ ] 1. 定义与边界
- [ ] 2. 产业链与利润池
- [ ] 3. 市场空间
- [ ] 4. 竞争格局
- [ ] 5. 阶段、周期与政策
- [ ] 6. 投资判断
- [ ] 7. 生成报告

## 阶段结论

### 阶段 N：[名称]
- **结论**：[一两句话；标注"已讨论确认"或"未经讨论"]
- **关键证据**：
  - 【事实】... [来源，时间]
  - 【推断】...
- **用户观点**：[用户在讨论中提出的判断、补充信息或关注点]
- **分歧与不确定性**：[尚未解决的分歧，什么信息会改变结论]
- **待核实**：
  - [ ] ...（建议去哪里查）
- **对核心问题的意义**：[本阶段结论如何回答核心问题]

## 信息来源
1. [来源名称，链接或出处，时间]

## 讨论记录（可选）
- [日期] 关键讨论和决定，例如"用户认为客户集中度风险可以接受，因为……"
```

## 记录要点

- **结论要能单独看懂。** 一周后用户回来，只看结论那一行就知道当时判断了什么。
- **用户观点要如实记录。** 即使用户的观点和你的判断不同，也要记下来；最终报告要体现用户的判断。
- **待核实事项要具体。** 写清楚要核实什么、建议去哪里查，方便用户自己去补。
