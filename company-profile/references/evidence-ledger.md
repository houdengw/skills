# 证据库

证据库 `evidence.jsonl` 是报告的唯一事实来源。正文的每一个事实都引用证据库中的条目，校验脚本也根据它来核对正文。

## 格式

每行一条 JSON，UTF-8 编码：

```json
{"id": "E001", "url": "https://www1.hkexnews.hk/....pdf", "title": "招股章程", "publisher": "港交所披露易", "tier": "T1", "date": "2025-12-30", "entity": "confirmed", "quote": "2022年、2023年及2024年，我们的收入分别为人民币57.4百万元、124.5百万元及312.4百万元", "locator": "第 312 页", "section": "经营与财务", "note": ""}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | `E001` 起顺序编号，一经分配不再改动，删除也不复用 |
| `url` | 是 | 原文链接。纸质或线下资料填空字符串，并填 `locator` |
| `title` | 是 | 原文标题，不要用摘要前几个字代替 |
| `publisher` | 是 | 发布方：港交所披露易、北京市科委、新浪财经、雪球用户×× |
| `tier` | 是 | `T1`–`T4`，见 `sources.md` |
| `date` | 是 | 发布日期 `YYYY-MM-DD`，不知道具体日可写 `YYYY-MM`。查不到填空字符串，脚本会提示 |
| `entity` | 是 | `confirmed` 本主体 / `related` 关联主体 / `rejected` 非本主体或无法确认 |
| `quote` | 是 | 原文摘录，照抄不改写，带单位和时点，一般 1–3 句 |
| `locator` | 否 | 页码、章节、表格编号，PDF 必填 |
| `section` | 否 | 预计归属的报告章节，方便整理事实表 |
| `note` | 否 | 补充说明：口径、"仅摘要"、关联主体是哪家、与哪条证据冲突 |

## 收录规则

- **一条证据对应一个可核对的事实点。** 一篇长文支撑多个事实时，拆成多条证据，各自摘录对应原文，`url` 相同即可。这样引用才精确，脚本也能逐条核对数字。
- **摘录要包含正文将要写的数字。** 正文写"研发人员 657 名"，`quote` 里就要有"657"。脚本靠这一点核对。
- **同一事实有多个来源时都收录**，正文引用等级最高的，冲突时并列引用。
- **被排除的资料也收录**，标 `rejected`，`note` 写明原因（如"同名企业，注册地上海，从事纳米材料"）。这样复查时能看到排除过什么。
- **不要事后修改 `quote` 去迁就正文。** 正文和原文对不上时，改正文。

## 关联主体的写法

`entity` 为 `related` 的证据，正文必须写明主体：

- 正确："其全资子公司北京智谱××科技有限公司中标……[E031]"
- 错误："公司中标……[E031]"
