# 企业画像

## 这个 skill 是做什么的

用户给出一个企业名称，你产出一份企业画像报告。读者通常拿它去做招商对接、投资初筛、合作洽谈、授信前摸底或客户拜访准备。

市面上的自动画像系统常见这些问题：引用编号对不上原文、把同名公司的资料写进来、正文数字和来源不一致、大量依赖自媒体而不读招股书、同一事实在各章反复出现、两次生成结果互相矛盾。读者一旦发现一处，整份报告就不可信了。

这个 skill 的做法是**先建证据库，再写报告，最后机器校验**：

1. **锁定主体**：用统一社会信用代码确定唯一的企业，列出所有可能混淆的同名、近名企业。
2. **采集证据**：每条资料进入证据库前，先确认属于本主体、标注来源等级，并摘录能支撑事实的原文。
3. **整理事实**：把证据整理成事实表，列出来源冲突和信息缺口，再分配每条事实归属的章节。
4. **写作**：正文只引用证据库中的证据（`[E012]`），数字必须在所引原文中出现，换算要写出计算过程。
5. **校验与渲染**：运行 `scripts/check_report.py`，修完所有错误后渲染成正式报告，编号由脚本统一生成。

## 工作目录

在当前工作目录下创建 `企业画像-[企业简称]/`，内含：

| 文件 | 内容 | 何时写 |
|---|---|---|
| `entity.md` | 主体锁定卡、检索计划、事实表、冲突与缺口 | 第 1、2、4 步 |
| `evidence.jsonl` | 证据库，每行一条证据 | 第 3 步，边查边写 |
| `draft.md` | 报告草稿，用 `[E001]` 引用 | 第 5 步 |
| `report.md` | 正式报告，由脚本生成，不要手改 | 第 6 步 |

用户带着已有的工作目录回来时，先读 `entity.md` 和 `evidence.jsonl`，在原有证据库上补充和更新，不要从头再查。这样多次生成的报告彼此一致，差异也能追溯到具体证据。

没有文件系统时，在对话中按同样结构输出证据表和报告，并人工完成第 6 步的核对。

## 第 1 步：锁定主体

**先读 `references/entity-lock.md`。**

找到企业的统一社会信用代码、登记全称、曾用名、常用简称、上市代码（如有）、注册地，填进 `entity.md` 的主体锁定卡。同时列出**易混淆主体**：同名或近名企业、母公司、子公司、分公司、同一品牌下的其他法人。

- **能唯一锁定时**：用一句话告诉用户锁定的是哪家（全称 + 信用代码 + 注册地），然后直接继续。
- **有多个候选时**：必须停下来问用户，列出候选企业（全称、注册地、成立时间、法定代表人），让用户选。不能自己猜。
- **用户只给了简称或品牌名时**（如"智谱""蔚来"），通常对应一个集团，默认锁定上市主体或运营主体，并说明集团内还有哪些重要法人。

同时确认报告用途，默认"通用画像"。用户说明了用途（招商、投资、合作、授信、拜访），按 `references/report-template.md` 中对应用途调整章节重点。用途不清楚时不必追问，用默认值并告诉用户可以改。

## 第 2 步：判断企业类型，制定检索计划

**先读 `references/sources.md`。**

企业类型决定先查哪里：

| 类型 | 优先读 | 说明 |
|---|---|---|
| 上市公司 | 招股书、最新年报和中报、交易所公告 | 法定披露是最全最准的来源，**必须先读**，再用网页补充最新动态 |
| 拟上市、新三板、发债企业 | 招股书申报稿、问询回复、挂牌公开转让说明书、募集说明书 | 同样有法定披露，往往被忽视 |
| 非上市中大型企业 | 工商登记、官网、政府网站、招投标、权威媒体 | 财务数据通常缺失，如实写明 |
| 中小微和初创企业 | 工商登记、知识产权、招投标、招聘、官网 | 公开信息少，报告短一些是正常的，不要用泛泛之谈凑篇幅 |

把检索计划写进 `entity.md`：每个章节准备去哪些来源查什么。检索词要带主体全称或信用代码，带简称检索时要预期会搜到同名企业。

## 第 3 步：采集证据

**先读 `references/evidence-ledger.md`**，里面有字段定义和收录规则。

每条资料要先过三道关，才能写进 `evidence.jsonl`：

1. **主体核对**：资料说的是不是锁定的这家企业？看全称、信用代码、注册地、法定代表人、业务是否吻合。是本主体记 `confirmed`；是母公司、子公司等关联主体记 `related`；不是或无法确认记 `rejected`。不确定的一律记 `rejected`，不要冒险。
2. **来源分级**：按 `references/sources.md` 标 T1–T4。AI 生成的页面（其他 AI 产品的输出、AI 写作站）不收录。
3. **摘录原文**：`quote` 字段放原文中能直接支撑事实的那一两句话，**照抄，不改写**。数字要连同单位和时点一起抄下来。只看到搜索摘要、没打开原文时，摘录摘要，并在 `note` 中写"仅摘要"。

采集要求：

- **关键事实至少要有 T1 或 T2 来源**：工商信息、股权结构、财务数据、员工人数、融资金额、重大处罚。只找到 T3、T4 时，正文标【待核实】。
- **重要数字交叉验证**：财务、估值、融资等数字至少找两个来源；不一致时两个都收录，留到第 4 步处理。
- **记下时点**：每条证据填发布日期；数字的统计时点（如"截至 2025 年 6 月 30 日"）写进 `quote`。
- **边查边写入证据库**，不要查完再凭记忆补录。

## 第 4 步：整理事实表

在 `entity.md` 中整理：

1. **事实表**：按章节列出核心事实，每条后面标证据 ID。每条事实只分配到一个**归属章节**，其他章节需要时写"见第 X 节"，不再重复展开。比如"研发人员占比"归"技术与研发"，"团队"一节就不再重复这个数字。
2. **冲突表**：来源之间不一致的数字或说法，写明各自的口径、时点和来源等级，给出采用哪个以及理由。常见原因是口径不同（注册专利还是公开申请、本地化部署还是企业级通用大模型）或时点不同。
3. **缺口表**：模板要求的内容中，哪些没查到。写明查过哪些来源，以及可以去哪里补。

这一步是为了让写作时不再临场判断事实，也是避免跨章节重复和前后矛盾的关键。

## 第 5 步：写作

**先读 `references/report-template.md`。**

在 `draft.md` 中按模板写作。引用和行文规则如下，校验脚本会逐条检查：

- **只用证据 ID 引用**：`……同比增长 131.9%[E012]。` 引用放在句末标点之前。不要写 `[1]` 这样的编号，也不要自己写参考来源列表。
- **有数字就要有引用**，而且这个数字要能在所引证据的原文中找到。单位换算（5740.9 万元写成 0.57 亿元）脚本能识别；派生计算（占比、人均、增速）要写出计算过程：`约 74%（计算：657÷883）[E021]`。计算时分子和分母口径要一致，比如"员工及顾问"不能除以"员工总数"。
- **评价性措辞要有出处**：如"第一梯队""领先""龙头""首家"。写成"据弗若斯特沙利文（招股书引用），按 2024 年收入计位列……[E005]"，说明是谁的评价。没有出处就删掉。
- **区分事实和判断**：判断要单独成句，写明依据，如"据此判断……，依据是第 4 节的收入结构和第 5 节的现金状况"。不写空泛的总结句。
- **数字带时点和口径**："2025 年全年收入 7.24 亿元"，不写"收入超 7 亿"。
- **查不到就写查不到**：在"信息缺口"一节如实列出，不要用通用描述填充篇幅。
- **表格**：数据表下方加一行 `来源：[E003][E007]`，脚本会把它应用到表格每一行。

## 第 6 步：校验与渲染

在工作目录上运行：

```bash
python scripts/check_report.py check 企业画像-[企业简称]
```

（`scripts/` 是本 skill 目录下的路径，运行时换成实际路径。）

- **错误**必须全部修复：数字在原文中找不到、引用了非本主体的证据、引用不存在的 ID、含数字的句子没有引用、评价性措辞没有出处、证据来自 AI 生成页面等。修复方式是改成原文数字、换成正确的证据、补计算过程，或者删掉这句话。**不能为了通过校验去改证据库的 `quote`。**
- **警告**逐条确认：只有 T4 支撑的关键数字、跨三个以上章节重复的数字、没有引用的陈述等。能修的修，不修的要有理由。
- 脚本只能检查数字和形式，检查不了语义。修完后，再**人工抽查**核心结论和每个章节的前两条引用：所引原文是否真的支持这句话。

全部通过后渲染：

```bash
python scripts/check_report.py render 企业画像-[企业简称]
```

脚本按首次出现顺序把 `[E012]` 重编号为 `[1]`，生成带原文摘录的参考来源列表，并填入来源构成统计，写出 `report.md`。

## 交付

把 `report.md` 交给用户，并在回复中用几行说明：

- 锁定的主体（全称 + 信用代码）；
- 来源构成（T1–T4 各多少条）；
- 最重要的 2–3 个信息缺口或数据冲突；
- 如果用户要用于对外发布、投资决策或授信，提醒哪几个关键数字建议再找原件核对。

不要在回复里复述报告内容。

## 不能联网时

不要凭训练数据生成画像：数字会过时，也无法引用，正是本 skill 要避免的问题。告诉用户无法检索，然后只提供两样东西：这家企业应该去哪些来源查什么（按 `references/sources.md`），以及一份待填的报告框架。
